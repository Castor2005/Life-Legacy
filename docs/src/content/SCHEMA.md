# Life & Legacy content schema (v4)

Authoritative content lives in `src/content/`. The engine **only reads and executes** these files — no game logic in content, no content hardcoded in the engine (see `src/engine/effects-*.js`).

## Schema versions & migrations (single source of truth: `src/engine/migrate.js`)

Three versions, three registries — bump rules:

| Version | Lives in | Today | Bump when… |
|---|---|---|---|
| `LL.SAVE_VERSION` | `migrate.js` (`LL.SAVE_VERSION = N`) | 7 | a `SAVE_MIGRATIONS` step is added (save shape changed) |
| `LL.CONTENT_VERSION` | `migrate.js` + `src/content/index.json` `contentVersion` | 4 | the content contract changes (new required event field, new op family, pack layout change) |
| `LL.EVENT_SCHEMA` | `migrate.js` (`LL.EVENT_SCHEMA = N`); per-file `"schema"` (default 1) | 1 | a breaking per-file change lands |

- **Saves**: `LL.SAVE_MIGRATIONS` = ordered `{v, id, desc, run}` steps (v4 identity-flags → v5 stats-appearance → v6 systems → v7 chat-focus-geo). `migrateSave()` upgrades any save with `S.v < step.v`, stamps `S.v = SAVE_VERSION`. Downgrade (`S.v > SAVE_VERSION`): data untouched, returns `"newer"`, callers warn. `validateSave(st)` pre-load gate (slot load, autosave continue, file import) rejects damaged saves with a reason instead of crashing. Rules: steps only fill missing fields (idempotent); NEVER edit an old step's behavior — append new steps.
- **Content**: `migrateEvent(ev)` upgrades files through `LL.EVENT_MIGRATIONS` (empty today — passthrough) before compile, in both the pack path and the fallback path. `checkContentVersion(v)` gates the index: `match` (ok) / `stale` (older index, warn) / `newer` (best-effort, warn) / `bad` (non-numeric). Tools (`validate-content`, `build-events`) parse the `LL.X = N` lines out of `migrate.js` — never hardcode a version in a tool.
- **Tests**: `src/tools/migration-test.js` (page_eval: legacy/mid/future/corrupt saves, idempotency, fresh-life stamp, content gate, event passthrough).

## Layout

```
src/content/
  index.json          # GENERATED: version + every pack (pack file lists)
  events/<id>.json    # AUTHORING TRUTH: one file per event (781)
  packs/*.json        # GENERATED: embedded event bodies per bucket (runtime reads THESE)
  SCHEMA.md           # this file
src/engine/content-fallback.js  # GENERATED: all events, lazy-loaded only if pack fetch fails
src/engine/effects-parse.js   # pure: expression grammar (parse + eval)
src/engine/effects-run.js     # pure: conditions, effect executor, event compiler
src/engine/effects-validate.js# pure: schema + semantics validation
src/engine/migrate.js         # versions (SAVE/CONTENT/EVENT_SCHEMA) + SAVE/EVENT_MIGRATIONS + migrateSave/validateSave/checkContentVersion/migrateEvent
src/tools/validate-content.js # runner (browser console or worker)
```

`index.json`:

```json
{
  "contentVersion": 4,
  "packs": [
    {"id":"baby","title":"Baby & toddler","type":"events","files":["first-word","eat-sand"],"minAge":0,"maxAge":4,"lazy":true},
    {"id":"mature","title":"mature","type":"events","files":["sx-awakening","co-client"],"minAge":18,"maxAge":120},
    {"id":"jobs","title":"Jobs","type":"data","source":"src/data/careers.js","provides":["jobs","majors","degrees"]}
  ]
}
```
- Event packs: `files` are event ids → `events/<id>.json`. `minAge/maxAge` = loader hint (which packs to fetch for an age). `lazy:true` = fetch on demand, not at boot.
- Dedup layout (v4): `young/adult/mid/senior` carry ONLY their exclusive events (range fits entirely inside the bucket — `adult`/`mid` may be empty files). The `mature` overlay (18-120) holds everything else 18+ exactly once: all `sx-`/`ow-`/`ex-`, all multi-bracket standards, all boundary events spanning the 18 line. `baby/kid/teen` are unchanged and still list every event touching them (boundary events therefore live in both sides). The engine loads `bucket(age)` + `mature` once (cached) at age ≥ 18, so eligibility is exact with no per-bracket duplication.
- Data packs: `source` = sync JS already in boot order; `provides` = GDATA keys. Listed so one index covers everything.

## Single source of truth (generated artifacts — NEVER hand-edit)
- `events/<id>.json` is the ONLY authoring truth. `packs/*.json`, `index.json` (pack file lists), and `src/engine/content-fallback.js` are all GENERATED by `src/tools/build-events.js` (`dedupeAdultPacks({write:true})`).
- The engine reads pack BODIES at runtime (never `events/`), so a hand-edited pack would ship silently. Three validator edges close this: pack coverage (index lists == event files), pack BODY deep-equality (every embedded event == its event file), fallback deep-equality.
- Workflow: edit `events/*.json` → run `dedupeAdultPacks({write:true})` → run `validate-content` (must be 0 errors). If validate-content reports `pack <id>/<event>: body differs` or `fallback: stale`, someone edited a generated file — regenerate, don't patch the artifact.
- Fallback policy: the snapshot stays COMPLETE (all events, ~622KB) by design — it is the only safety net when pack fetching fails, and it is lazy-loaded (zero parse/memory cost in normal play, freshness enforced by the validator). Do not "diet" it by dropping buckets, and do not split it per-bucket: one file means one script-injection fallback path (see `contentFallbackFor`), while N files would mean N failure branches for the rarest path in the game. 622KB of repo bytes buys guaranteed coverage; normal play never pays it.

## Event file

```json
{
  "id": "first-word",
  "pack": "baby",
  "title": "First word!",
  "minAge": 1, "maxAge": 2,
  "tags": ["baby","family"],
  "weight": 1,
  "preconditions": null,
  "text": "You babbles ...", 
  "choices": [
    {"label":"Cheer them on","hint":"happiness+","effects":[{"op":"stat","key":"happiness","delta":8}],"outcome":"The word is 'mama'!"}
  ]
}
```
- `id`: unique, matches filename. `title`: plain string (no code).
- `minAge/maxAge`: integers, 0..120, min<=max.
- `tags`: non-empty string array (life-stage + systems, e.g. `teen`, `crime`, `company`, `sex`, `netori`).
- `weight`: integer 1..10, default 1 (uniform today; reserved for era/mod tuning).
- `preconditions`: null or a **rule** (below).
- `text`: string template with `{{expr}}`, or `{"lets":[{"name","expr"}],"template":"..."}`.
- `choices`: 1..4 entries; each has `label`, `hint` (plain strings), `effects` (op list, possibly empty), `outcome` (template, required).

## Rules (preconditions, branch conditions)

```json
{"all":[...]} | {"any":[...]} | {"not": R}
{"p":"stats.smarts","gte":45}            // eq ne gt gte lt lte, literal value
{"p":"relationships.partner","exists":true}
{"p":"traits","includes":"brave"}
{"p":"company.sector","in":["food","trade"]}
{"some":{"arr":"relationships.children","where":{"all":[{"p":"$it.age","gte":5},{"p":"$it.age","lte":6}]}}}
{"someChild":{"min":5,"max":6}}
{"partner":"exists|dating|married|single|lover"}
{"job":"employed"} | {"jailed":true}
{"call":"ownLawAllows"} | {"call":"ownLawDenies"}
```
Paths are safe S-paths (`s.` implied; `$it.` inside `some`). Missing intermediates evaluate to `undefined` (never throw). Value comparisons (`eq/ne/gt/gte/lt/lte/in`) must target leaf paths — comparing a whole container object (e.g. `stats`) is always false, and the validator rejects it.

## Expressions (values, templates, lets)

Small safe grammar — literals, paths, `+ - * / %`, comparisons, `&& || !`, ternary, parens, array literals, whitelisted calls:
`rnd(), clamp(x,a?,b?), min(...), max(...), floor(x), round(x), ceil(x), len(a), keys(o), topKey(o), topKeys(o[,n]), randName(), partnerName(), childInAge(a,b), claimWhere(field,op,val), lastClaim(), topClaim(f), firstName(), lastName(), where(arr,field,op,val), whereAll(arr,field,op,val), whereLast(arr,f1,op1,v1[,f2,op2,v2]), firstWhereMap(arr,map,op,val[,neg]), topBy(arr,f), lowBy(arr,f), hasClaim(name), alphaName(), haremCount()` + methods `.length .join(sep) .includes(x) .indexOf(x) .toLocaleString()` (methods also work on array literals, e.g. `[].join(", ")`; `where(...)` chains filter left-to-right, `[0]`-style picks use `where` last).
`firstWhereMap` returns the first element of `arr` whose `map[el]` passes `op val` (negated when the 5th arg is truthy); missing map keys count as `-Infinity`.
No statements, no assignment, no `;`, no `new`, no `function`, no `window/document/eval`.

Templates: `{{expr}}`; `undefined`/`null` render as `""`.

## Effects (op list, executed in order)

Control: `let{name,expr}` · `branch{cond,then,else?}` · `chance{p,then,else?}` (p number 0..1 or expr) · `forClaims{as?,idxAs?,body,match?,limit?,sortBy?,desc?,from?}` · `forChildren{as?,body}` · `returnIf{cond,outcome}` (stop + set outcome) · `outcome{tpl}` (template string; last one wins) · `call{fn,args?,as?,asOutcome?}` (named system fn from registry; `args` values are `{expr}` objects or literals).
Values: `stat{key,delta}` (STAT_KEYS + `stress`, which routes to the top-level `S.stress` meter; clamped 0..100; `delta` is an expr string) · `money{amount[,floor]}` (expr, can be negative) · `set{path,value}` (S-paths; numeric segments allowed for array indices, e.g. `relationships.children.0.rel`) · `flag{key,value}` · `edu{path,value}` · `grades{delta}` · `salary{value}` (expr) · `perf{delta}`.
Social: `jobSet{id}` · `jobLose{}` · `partnerRel{delta}` · `partnerMarry{}` · `partnerClear{}` · `partnerSet{name,rel,married,age}` (name/exprs evaluated) · `addPet{name,petType,rel}` · `addChild{name,age,rel}` · `addFriend{name,rel}` · `childPath{path,value}` (in forChildren, `$it` = child) · `claimPath{path,value}` (in forClaims, ref `$it`) · `claimRemove{ref}` · `claimSplice{index}` · `claimPop{as?}` · `claimsClear{}` · `arrPush{target,value}` (local array lets) · `setv{target,path,value}` (field write on a lets/loop var holding a live object; relative paths may start with an index) · `crewAdd{name?}` · `crewDrop{as?}`.
Sex/ownership: `kink{id}` (literal id) · `corr{delta[,name]}` (expr strings) · `xp{n}` · `skill{delta}` · `stamina{delta}` · `protection{bool}` · `scandal{delta}` · `addiction{delta}` · `pregScares{}` · `sexset{path,value}` · `lovAdd{name}` (dedup, capped 8) · `lovPush{name}` (legacy push + slice(-8) + partners++, no dedup) · `lovClear{}` · `levOn{target,secret}` · `levOff{holder,secret}` (plain push, no side effects) · `levOnClear{}` · `histLog{name,acts,forced?}` (acts are expr strings) · `pregSet{name,state,ctrl,child?}` · `claimAdd{name,ob?,os?,stage?}` · `claim{ref,path,value}` · `haremAlphaSet{name}` · `haremAlphaClear{}` · `netori{field,delta}` · `lawNote{label}`.
Meta: `tryPromote{why,asOutcome?,as?}` where `why` is an `{expr}` object (evaluated via call-arg rules).

Named `call` fns (implemented in engine systems, allowlisted here): `sex.ensure`, `sex.kink`, `sex.claim` (`{name,ob,os,stage}`), `sex.ownClaim` (`{name,via,ob,os}`), `sex.corr`, `sex.hist` (`{name,acts,forced}`), `sex.force` (`{name}`), `sex.preg` (`{name,mult,ctrl}`), `sex.addCorr`, `law.check`, `career.tryPromote`, `career.eligible`, `own.cashoutLeverage` (covers the leverage-crown cashout + claims top-up ritual).
Named predicates: `ownLawAllows`, `ownLawDenies`.

## Validator rules
Required fields + types; id uniqueness + filename match; age sanity; tags/weight ranges; choices 1..4 with label/hint/effects-array and a terminal outcome; every op known with required args; every expr parses (same parser as engine, so `${{expr}}` money templates and prose with sentence-final "window." are accepted); every template parses; every rule valid (leaf `{p|v: path, comparator: literal}`, no value comparisons on whole container objects, `all/any/not`, `partner/job/jailed/some/someChild/count/call/expr`); numeric path segments allowed for array indices; no JS in exprs (backticks, `;`, `function`, `=>`, `window.`, `document.`, `eval(`, `${`); all index files resolve; every event sits in exactly its home packs (each intersecting under-18 bucket, plus either its single exclusive adult bucket or the `mature` overlay); every event body embedded in each pack file deep-equals its `events/` source (rebuild, don't hand-patch); fallback snapshot must deep-equal the event files (rebuild via `build-events` `dedupeAdultPacks({write:true})`).
